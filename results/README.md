# Results

Output files from the runs reported in the paper, so results can be inspected
without re-running anything. Each entry names the command that produces it.

Caches and checkpoints are deliberately not included: they are inputs and
intermediate resume state, not results, and the extraction caches are large.

| File | What it is | Produced by |
| --- | --- | --- |
| `results_qwen.json` | Primary synthetic benchmark with the Qwen extractor. 12 arms including four ablations, 5 seeds, `per_category=25`, `tau=0.8`. Also carries `significance_vs_best_baseline`, `write_outcomes`, `efficiency`, `threshold_sweep`, `stress`. | `python -m ocm.scripts.run_experiments` (Qwen extractor configured) |
| `results_offline.json` | Same harness with the offline mock extractor: 8 arms, 5 seeds. Runs with no GPU and no network. | `python -m ocm.scripts.run_experiments` (defaults) |
| `results_longmemeval.json` | LongMemEval `knowledge-update` oracle arm (LM-O) plus the abstention split, over 47 annotated questions. | `run_7e_local.py`, or notebook cell 7e |
| `lmo_durable_state.json` | LM-O scored with durable-state outcomes rather than answer recall. Carries a `_meta` provenance block: dataset digest, annotations digest, annotating model, code revision. | `run_lmo_durable_state.py` (see below) |
| `governance_examples.json` | Per-write governance decisions for `B3` over 780 examples: quarantine-reason histogram, sampled decisions, and a false-quarantine breakdown. | `python -m ocm.scripts.run_experiments` |
| `longmemeval_kupdate_annotations__Qwen_Qwen2.5-14B-Instruct.json` | **Input, not a result.** The 47 gold value trajectories LM-O is scored against, generated by Qwen2.5-14B-Instruct and validated against the corpus's own answers. Included because LM-O cannot be reproduced without it. | `annotate_file` (see the root README) |

## Reproducing `lmo_durable_state.json`

The only file here that runs in about two minutes on a laptop:

```bash
python run_lmo_durable_state.py \
  --annotations results/longmemeval_kupdate_annotations__Qwen_Qwen2.5-14B-Instruct.json \
  --data data/longmemeval_oracle.json \
  --arms B0,B2,Bsup,Bevi,B3 \
  --embeddings local \
  --out results/lmo_durable_state.json
```

The corpus is fetched automatically if absent. Expect `DSC 0.00` for `B0`/`B2`
against `100.00` for the three governed arms, and 50 durable violations against 0.

## Reading these files

`decisive_metrics` holds `task_success`, `contradiction_rate` and
`constraint_violations`, each as `mean` with a bootstrap interval over the five
seeds. `write_outcomes` holds accepted / superseded / quarantined / rejected counts
**summed across seeds**, so divide by `len(seeds)` for a per-seed figure.

Confidence intervals on the durable-state file are zero-width. That reflects
deterministic replay, not zero uncertainty.

Two things in `results_qwen.json` are easy to misread:

- `task_success` is recall over the rendered answer *plus every retrieved item*,
  so it rewards retaining values. An arm that keeps stale values scores higher on
  it than one that retires them, which is why `B3` sits below `B0` there while
  holding constraint violations at 0.00 against `B0`'s 50.72.
- `Bsup` records *more* violations than the ungoverned arms (64.54 vs 50.72).
  Supersession alone, without the contradiction gate, is not a strict improvement.
