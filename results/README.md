# Results

Output files from the runs reported in the paper, so results can be inspected
without re-running anything. Each entry names the command that produces it.

Caches and checkpoints are deliberately not included: they are inputs and
intermediate resume state, not results, and the extraction caches are large.

| File | What it is | Produced by |
| --- | --- | --- |
| `results_qwen.json` | Primary synthetic benchmark with the Qwen extractor. 12 arms including four ablations, 5 seeds, `per_category=25`, `tau=0.8`. Also carries `significance_vs_best_baseline`, `write_outcomes`, `efficiency`, `threshold_sweep`, `stress`. | `OCM_Colab.ipynb` §6b |
| `results_offline.json` | Same harness with the offline mock extractor: 8 arms, 5 seeds. Runs with no GPU and no network. | `python -m ocm.scripts.run_experiments`, or `OCM_Colab.ipynb` §5b |
| `results_longmemeval.json` | LongMemEval `knowledge-update` oracle arm (LM-O) plus the abstention split, over 47 annotated questions. | `run_6e_local.py`, or `OCM_Colab.ipynb` §6e |
| `results_longmemeval_e2e.json` | LM-R end-to-end abstention split (30 questions, real Qwen extraction from raw text). Carries `_run_manifest`: the run fingerprint, dataset digest, cache identities and entry counts. All four arms score 100.0 abstention accuracy, so this split does not separate them. | `run_6f_local.py`, or `OCM_Colab.ipynb` §6f |
| `lmo_durable_state.json` | LM-O scored with durable-state outcomes rather than answer recall. Carries a `_meta` provenance block: dataset digest, annotations digest, annotating model, code revision. | `run_lmo_durable_state.py` (see below) |
| `governance_examples.json` | Per-write governance decisions for `B3` over 780 examples: quarantine-reason histogram, sampled decisions, and a false-quarantine breakdown. | `OCM_Colab.ipynb` §6c |
| `longmemeval_kupdate_annotations__Qwen_Qwen2.5-14B-Instruct.json` | **Input, not a result.** The 47 gold value trajectories LM-O is scored against, generated by Qwen2.5-14B-Instruct and validated against the corpus's own answers. Included because LM-O cannot be reproduced without it. | `annotate_file`, or `OCM_Colab.ipynb` §6e |

## 1. Reproducing `lmo_durable_state.json`

The only file here that runs in about two minutes on a laptop:

```bash
python run_lmo_durable_state.py \
  --annotations results/longmemeval_kupdate_annotations__Qwen_Qwen2.5-14B-Instruct.json \
  --data data/longmemeval_oracle.json \
  --arms B0,B2,Bsup,B3 \
  --embeddings local \
  --out results/lmo_durable_state.json
```

The corpus is fetched automatically if absent. Expect `DSC 0.00` for `B0`/`B2`
against `100.00` for the three governed arms, and 50 durable violations against 0.

## 2. File structure

`decisive_metrics` holds `task_success`, `contradiction_rate` and
`constraint_violations`, each as a `mean` with a bootstrap interval over the seeds
listed in `seeds`.

`write_outcomes` holds accepted / superseded / quarantined / rejected counts
**summed across seeds** — divide by `len(seeds)` for a per-seed figure.

Intervals in `lmo_durable_state.json` are zero-width because that run is a
deterministic replay over a single pass, not because uncertainty was measured as
zero.

Durable-state buckets in `lmo_durable_state.json` are `correct`, `stale`, `split`,
`abstained` and `missing`; the definitions are in
[`ocm/evaluation/durable_state.py`](../ocm/evaluation/durable_state.py).
